The two-level model

A mode owns a glyph. A variant is a selectable profile sitting on a tier the mode declares. The grouping is declared, not inferred — the stable key is the tier (base_profile), and the declaration says which tiers are variants of which mode.

modeglyphdeclared tierslive variants
Powersave leaf Powersave · Superpowersave Powersave · Powersave++ (2)
Balanced scales Balanced Balanced (1 — no variant control)
Performance engine Performance · Ultraperformance Performance · Performance++ (2)
unlisted fallback declares no tier any unmapped base_profile, marked unmapped tier

Why declare, not infer? profile_name is user-editable, so stripping a ++ suffix breaks the moment a profile is renamed. base_profile IS the stable key but yields five distinct tiers, not three — Powersave++ → Superpowersave, Performance++ → Ultraperformance, both genuinely different tiers to the daemon. So a tier-only rule asks for five glyphs. The grouping is therefore an explicit declaration; an unlisted tier falls back to the neutral glyph rather than disappearing. Full argument drawn in key-declaration.html.

Mutual exclusion — the defect the previous attempt shipped

Three overlays each own a full-screen click-catcher: the settings panel, the Wi-Fi popup and this battery panel. Two open at once means two live catchers, and the top one swallows every click outside itself — so the panel underneath is not merely ugly, it is unreachable. Opening any one of the three MUST close the others; the design keeps the existing rule as a hard requirement of the selector's host:

settings-panel/state.open() calls closeBatteryPopup(); the battery bar widget calls close() and closeWifiPopup() before toggleBatteryPopup(); and BatteryPopup stands down if wifiPopupVisible(). Coordination lives in the callers, never in the state module.
