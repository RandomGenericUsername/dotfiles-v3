Explainer — body order and the two structural rules

Rule 1: the header is a SIBLING of the scrolledwindow, never a child. This is the single lesson SubviewHeader.tsx documents — a header inside the scrolled window scrolls away, so two surfaces sharing one NavHeader behave differently. Both Bluetooth surfaces put the header outside.

Rule 2: the power control in the header is always a Gtk.Switch. Wi-Fi's popup and subview both put WifiSwitch there; Bluetooth's subview currently puts a 22px bare glyph in the same slot. A user who learned "the pill on the right of this header is the radio" would get a bare glyph in one Bluetooth surface and the pill in the other, at identical screen positions. The glyph is not lost — CapabilityTile keeps IconToggle on the main-view tile, where the glyph's job is to say which capability this is and the switch's is to say is it on.

Why the subtitle says words and not numbers

WifiRow's subtitle is Saved / Secured / Open network — words, never strength percentages, because the leading glyph already is the strength. The shipped Bluetooth row broke that rule: it had no leading glyph, so the dBm number was the only strength cue. Adding the leading settings-panel/signal-* glyph means the number has become redundant — so it moves to the glyph's tooltip. Two encodings of one number is noise. This changes one already-approved row detail and needs owner sign-off (see DESIGN.md §Components, Meta stack).

Discover-then-reveal

Available Devices expansion is manuallyToggled || nearbyCount > 0 — see the third mock above, where the section revealed itself and flipped ▸ → ▾ the moment a neighbour was found. Why: a discovery run starts the instant the surface becomes visible, so a collapsed section fills within a second or two of opening. A purely manual toggle would show an empty popup and then quietly populate a section the user never opened. Collapsing only while it is genuinely empty gives the audio popup's "quiet when nothing is happening, dense when the graph is busy" behaviour and guarantees the section is never a trap. Toggling it closed while rows exist is allowed — the user's choice wins — and the count is not re-forced until the section empties again.

Footer row

Bluetooth Settings › launches bluetoothctl — the Bluetooth analogue of the Wi-Fi popup's Wi-Fi Settings › opens nm-connection-editor row, down to the wrap-not-ellipsize rule on the note (an unwrapped Gtk.Label reports its full text as natural width and would push the surface off the monitor). If the spawn fails, the message surfaces in the existing .settings-message line — never a dialog.
