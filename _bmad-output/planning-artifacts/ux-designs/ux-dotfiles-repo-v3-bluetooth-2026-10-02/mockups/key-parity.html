⑤ Wi-Fi ↔ Bluetooth — the parity matrix

The mandate is full parity with the Wi-Fi panel. This page is the audit trail for that claim: every structural element of WifiPopup.tsx / WifiContent.tsx, the Bluetooth counterpart, the settings-* class they share, and the real icon key. Then every place the two domains genuinely differ, with its own row — argued, never smuggled in.

Named divergences, in one place · parity-divergence

Six places where BlueZ and NetworkManager genuinely differ. Each gets a row of its own because a divergence that is not written down is a divergence nobody can review.

#DivergenceWhy it is not a parity bug
1 No password prompt, therefore no ON_DEMAND keymode. The shipped pairing agent is NoInputNoOutput. Nothing Bluetooth shows accepts typed input, so an ON_DEMAND grab would buy nothing and cost the first click and the same-spot collapse. The Wi-Fi rule is adopted verbatim and simply has nothing to gate on yet.
2 The row leads with a settings-panel/signal-* glyph, where Wi-Fi leads with settings-net-signal. Same slot, same class, same 30 px box — but a different art family. Bluetooth strength is dBm with an rssi = 0 "not seen" sentinel and no percentage; there is nothing to map into wifi-signal-*. The signalVariant() thresholds already shipped in BluetoothContent.tsx, so this is zero new art. Absent entirely when rssi ≥ 0, which is why out-of-range rows have no glyph.
3 A second row action (Unpair, settings-rowact subtle). Bluetooth pairing is a trust relationship with a remembered device key; forgetting it is a real, deliberate act. Wi-Fi rows have nothing equally destructive in the action slot, so there is nothing to pair the second button with.
4 The inline unpair confirm, and the design's one new class settings-rowact.danger. It follows from #3, and it is inline precisely so it costs no new window, no modal stack and no reflow. The destructive path is one click longer than the safe one — the only asymmetry that matters — and the confirm is not colour-alone: the button says Unpair device and Keep sits beside it. Border + text take @color_03; hover lifts to @color_11.
5 An Audio output detail row with no Wi-Fi counterpart. This is the row that closes the bug the design exists for. BlueZ can report Connected while PipeWire has not routed the stream, and today that failure is completely invisible — the panel claims success and the sound stays on the speakers. routeAudioToDevice records the endpoint it actually defaulted into bluetoothAudioTarget, and the surface reports it rather than auto-routing silently and leaving the user guessing. It also drives the bar indicator's active state. NetworkManager has no such second hop to get wrong.
6 A new bluetooth bar icon group, where Wi-Fi rides inside network's states. A structural fact of the icon manifest, not a styling choice: there is no Bluetooth bar group to borrow, and borrowing network would have put Bluetooth's four states in Wi-Fi's six. Bar state is carried by art (slashed / bare / hollow dot / filled dot) with no variant-level tint pin, so the guard keeps retargeting the group on every wallpaper.
