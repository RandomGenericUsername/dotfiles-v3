- (decision) AD-1 Runtime core uses hexagonal architecture: dependencies point inward (infrastructure -> core), never core -> infrastructure. Binds all runtime code. Prevents core depending on subprocess/FS/persistence detail. Rule: domain/ports/adapters/application/cli layering, mechanically enforced by a per-package test_layering.py mirroring provisioning.
- (decision) AD-2 Derived artifacts live in a layered content-addressed cache: one cache level per derivation layer (wallpapers, palettes, effects, icons), each entry keyed by the hash of ALL its derivation inputs, not just the wallpaper. Prevents stale-serving when templates/catalog/mappings change. Rule: cache dir = cache/<layer>/<input-hash>/.
- (decision) AD-3 Runtime store is JSON/dict-like, not SQLite: current.json (manifest) + history.jsonl (append-only) + per-entry meta.json co-located with cache artifacts. The filesystem (cache/ + current/ symlinks) is the authority; the store is an index + history, re-derivable except history. Prevents SQLite schema/migration/opacity overhead for a single small document.
- (decision) AD-4 history.jsonl is must-not-lose: the one authoritative store piece. Append-only, atomic append, never overwritten. Prevents drift-history data loss. Rule: every reconcile appends one history line before desktop reload is considered complete.
- (decision) AD-5 state_root = /dotfiles/ (default ~/.local/state/dotfiles/), fully runtime-owned. Runtime owns cache/ + current/ + current.json + history.jsonl. Provisioning owns the install spine (/dotfiles/). Prevents §11 boundary blur. Rule: runtime never writes under install spine after first-run seeding; provisioning never writes under state_root.
- (decision) AD-6 Desktop swap = repointing symlinks under current/ (one symlink per consumer path, each atomic tmp+rename). Zero file copying. Symlinks lead, current.json follows: on crash the desktop is consistent and the store lags, recoverable on next run. Prevents copy inefficiency and partial-state on crash.
- (decision) AD-7 CSG/WEG output directed per call via env-var override (COLORSCHEME__OUTPUT__DIRECTORY, WALLPAPER__OUTPUT__DIRECTORY, ICON_RENDERER__*), never by editing provisioning-rendered settings.toml. Prevents provisioning coupling. Rule: settings.toml stays provisioning-owned; runtime overrides output paths per cache-entry via env chain.
- (decision) AD-8 Content hashing is SHA-256, and hash_algorithm is recorded in every meta.json. Prevents silent cache invalidation if the hash function changes. Rule: cache entry dir names are the hex hash; meta.json records hash_algorithm: sha256 and input/artifact hashes.
- (decision) AD-9 Cache population uses the staging-dir pattern: generate into cache/.staging-<pid>/, then os.rename to the final cache/<layer>/<hash>/ entry. Prevents concurrent-population race (two wallpaper set calls) and partial entries. Rule: an existing final entry is never overwritten; staging is discarded if the target already exists.
- (decision) AD-10 Domain model is a derivation graph, not the flat DesktopState in docs/99 §14: WallpaperEntry -> PaletteEntry and EffectsEntry; PaletteEntry -> IconsEntry. Each node knows its input hashes and artifact_hashes. Prevents flat model's invalidation blind spot. Rule: DesktopState = projection of the current derivation outputs (the current.json manifest).
- (decision) AD-11 First-run self-seeding: when current.json is absent and provisioning's <install>/generated/ output exists, runtime seeds cache/<layer>/ entries from provisioning's default output (default.png palette/effects/icons), writes current.json, creates current/ symlinks, appends history (trigger: seed). Prevents manual seeding and §11 violation by provisioning. Rule: seeding is one-time; after it, runtime never reads install spine.
- (decision) AD-12 Phase 2 execution model is synchronous and imperative (per docs/99 §22): dotfiles wallpaper set -> ApplyWallpaperUseCase -> reconcile -> generate missing artifacts -> write configs -> reload desktop -> persist. No daemon, async, event bus, plugin system, distributed execution (docs/99 §26). ADOPTED from existing doc.
- (decision) AD-13 Runtime core follows the provisioning-as-built nested hexagon layout: src/runtime/src/runtime/{domain,ports,adapters,application,cli} + tests/architecture/test_layering.py + tests/unit|integration, packaged as its own uv package. Ratified from brownfield sweep (src/provisioning structure + docs/99 §8.0). Resolves docs/99 §9 drift: NOT src/core/ + src/infrastructure/. Prevents two divergent package styles.
- (decision) AD-14 Domain purity contract mirrors provisioning's layering test: domain imports only stdlib allowlist (dataclasses, enum, typing, collections, functools, re, __future__), never os/subprocess/shutil/pathlib, never Path FS method calls; ports are ABCs (I prefix) or Protocol; adapters hold all I/O. Prevents I/O leaking into the core. Rule: same mechanical enforcement as src/provisioning/tests/architecture/test_layering.py.
- (decision) AD-15 Cross-package boundary mirrors provisioning Rule 5: runtime imports only cli_output (and declared deps); forbidden set includes provisioning, core, infrastructure, color_scheme_generator, wallpaper_effects_generator, icon_templates_renderer, config_assembler_engine, oci_runtime. Runtime reads provisioning OUTPUT (files/settings), never imports provisioning code. Prevents bounded-context coupling. Rule: runtime discovers install spine paths from rendered settings.toml / XDG, not from provisioning imports.
- (decision) AD-16 Wallpaper file is hardlinked into cache/wallpapers/<hash>/wallpaper.png at population time (copy fallback only when source and cache are on different filesystems). Prevents source-file move/delete breaking the cached entry; zero-copy on same FS. Rule: cache entry is self-contained; hardlink keeps inode alive after original removal.
- (decision) AD-17 Consumer wiring: desktop components read through current/ symlinks. Hyprland colors.conf -> current/colors.conf; Waybar colors.css -> current/colors.gtk.css; Hyprpaper wallpaper -> current/wallpaper.png; ITR color_scheme.path -> current/colors.yaml. Provisioning flips ~4 symlink targets: compositor_configs (colors.conf + colors.css from copies to symlinks), hyprpaper conf template (wallpaper path -> current/wallpaper.png), settings (ITR color_scheme path -> current/colors.yaml), verify criterion 6 (generated/palettes OR current/colors.yaml). Prevents stale copy divergence on swap. Rule: ~/.config/hypr/colors.conf and waybar/colors.css chain spine -> state_root/current -> cache entry.
