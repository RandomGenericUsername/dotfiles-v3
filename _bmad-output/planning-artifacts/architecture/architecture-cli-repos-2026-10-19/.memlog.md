- (constraint) Six targets only: cli-output, config-assembler-engine, oci-runtime, color-scheme-generator (csg), wallpaper-effects-generator (weg), icon-templates-renderer (itr); dotfiles-runtime stays.
- (constraint) Order is fixed: shared libs first (cli-output, config-assembler-engine, oci-runtime), then itr, weg, csg.
- (constraint) Dependency direction fixed by the human: CLIs to shared libs; never CLI to CLI; dotfiles runtime/provisioning to pinned artifacts; no uv workspace across repos.
- (constraint) Every new repo is mu-strict from birth: AGENTS evidence contract, tickets framework, worktree guard, hash-pinned skills, openspec, Makefile, per-repo CI.
- (constraint) Per-target migration loop is strictly sequential: extract and tag, rewire dotfiles to the pin, validate by execution, delete the in-tree copy, merge; next target only afterwards.
- (decision) AD-1 dependency direction one-way: libs are leaves, CLIs depend on libs, dotfiles consumes pinned artifacts; graph forbids CLI-to-CLI and runtime-imports-CLI.
- (decision) AD-2 one package per repo and repo root equals package root: pyproject.toml, src/<import_name>, tests/, docker/ (csg+weg only), openspec/, tickets/, Makefile; the src/cli-tools plus src/shared layout dies with the split.
- (decision) AD-3 consumption by immutable git tag only: no path sources, no editable shared libs, no submodule, no workspace; uv.lock records the resolved commit; published tags are never moved or deleted.
- (decision) AD-4 the runtime-to-CLI invocation contract lives in cli-output as versioned data plus a pytest conformance kit; runtime and each CLI execute the same kit from the same pinned cli-output version, so argv/env/artifacts cannot drift without a package version bump.
- (decision) AD-5 container builds use the CLI repo root as context; Dockerfiles COPY only in-repo paths; shared libs enter the image from the pin recorded in the repo lock; no sibling-repo COPY survives.
- (decision) AD-6 oci-runtime replaces the monorepo marker with resolve_build_context (repo root marker: pyproject.toml plus src/<import_name>), keeps resolve_source_root as a deprecated compatibility alias for one minor because old installed tools still call it.
- (decision) AD-7 image build ownership: the CLI repo owns its Dockerfile and the build verb; dotfiles provisioning owns the pin, the checkout, the trigger and the image-exists verification; no repo builds an image whose Dockerfile it does not own.
- (decision) AD-8 tests are hermetic by rule: every suite passes with empty HOME and XDG directories and an unrelated cwd; the fix belongs in tests (autouse fixture) not in the resolver, because S3 proves XDG precedence is intended behavior.
- (decision) AD-9 release ritual: semver tag vX.Y.Z per repo with version continuity from today pyproject versions, CI builds sdist and wheel and attaches them to the GitHub Release, PyPI is deferred; each consumer pin bump is its own commit.
- (decision) AD-10 provisioning addressing: cli-tools.yaml entries become name plus repo plus tag; the role shallow-clones repo at tag into the install dir, installs the tool from that checkout and builds images from it; every asset source that pointed into a package tree is re-addressed to the pinned checkout.
- (decision) AD-11 pin verification: verify mirrors every pin with independent literals and asserts the tag by execution (checkout path contains the tag, installed version equals the tag); deploy-coverage asserts the consumption shape, the pin parity and the absence of the retired trees.
- (decision) AD-12 mu-strict birth checklist is the definition of done for creating a repo, not a later cleanup; a repo without the checklist is not a valid extraction target.
- (decision) AD-13 destructive-last migration: the in-tree copy is deleted only after the pinned wiring is proven by execution in the same slice; rollback is the pin, plus a revert of the deletion commit.
- (decision) AD-14 test ownership: the 195 tracked test_*.py files move with their packages and are gated by the new repos CI; dotfiles stops running them and asserts their trees are gone.
- (decision) AD-15 openspec ownership follows code ownership: package-specific specs move to the owning repo, the nested src/cli-tools/openspec moves to csg archive, historical archives stay in dotfiles as immutable history with a pointer.
- (decision) AD-16 backward compatibility window: installed old CLIs keep running because runtime coupling is PATH plus env plus output-dir only; an old CLI cannot build images from a new repo layout, so image builds require the pinned checkout of the matching tag until the in-tree copy is deleted.
