- (note) Source: docs/01-dotfiles-provisioning-phase1-plan.md (approved seed document, companion to docs/99-dotfiles-hexagonal-architecture.md).
- (note) Phase 1 = Machine State Reconciliation (architecture doc Domain 1, §4); it must never do Desktop Runtime Reconciliation (Domain 2, §4).
- (decision) Backend is Ansible (matches §9 src/provisioning/ansible/ repo tree); Python orchestrator shells to ansible-playbook.
- (decision) Multi-distro target: Arch (pacman + AUR) and Debian family (apt); distro branching is Ansible-native via ansible_facts and group_vars/{arch,debian-family}.yml; Python side stays distro-agnostic.
- (decision) CLI tool install (csg, weg, icon-renderer) is an Ansible task using 'uv tool install' against repo paths, inside the cli_tools role; not a separate Python adapter.
- (decision) Bootstrap entry is scripts/bootstrap.sh: pre-seeds Python+uv, then execs 'dotfiles-provision bootstrap' (solves chicken-and-egg).
- (decision) Install dir is $XDG_DATA_HOME/dotfiles/ (default ~/.local/share/dotfiles/); provisioning resolves it at plan time and bakes absolute paths into rendered settings files.
- (decision) Settings authoring is provisioning-authored Jinja templates rendered by Ansible template module; the csg/weg dump-* commands are NOT used by provisioning and remain user-facing conveniences.
- (decision) Persistence is JSON snapshots (provisioning-state.json); state is small.
- (decision) Phase order: provisioning first (Phase 1), runtime reconciliation core second (Phase 2); runtime legitimately assumes the env exists (§12).
- (decision) CSG templates dir default is Option A: deploy bundled templates to ~/.config/color-scheme/templates/ so the existing XDG resolver finds them with no env var and no runtime flag.
- (constraint) §11 boundary: src/provisioning is its own uv package importing cli-output only; never core, infrastructure, or the CLI-tool packages; knows machine state only (no wallpaper invalidation, palette, or cache logic).
- (constraint) Provisioning establishes operational capability only; it does not reconcile the desktop (§25).
- (constraint) The four §12 runtime preconditions (binaries installed, assets placed, filesystem structure exists, settings files parseable) must be assertable via VerifyCapabilityUseCase without reaching into provisioning internals.
- (constraint) Per-tool settings files must render and parse exactly: CSG output.directory; WEG output.directory + processing.temp_dir; ITR output.output_dir + templates.dir + color_scheme.path (absolute paths into the install dir).
- (constraint) ITR settings resolver is active (all commands call config_resolver.resolve); ITR has no dump command so provisioning writes its settings.toml directly (4 keys).
- (constraint) Distro differences are isolated to group_vars; the Python orchestrator must never branch on distro.
- (capability) CAP-1 | intent: An operator can diff desired machine state against actual state before any mutation. | success: 'dotfiles-provision plan' prints a desired-vs-actual execution plan with no system changes.
- (capability) CAP-2 | intent: An operator can apply provisioning idempotently and re-runnably. | success: 'dotfiles-provision apply' runs the Ansible playbooks and persists provisioning-state.json; re-running produces no drift.
- (capability) CAP-3 | intent: An operator can verify the machine satisfies the §12 runtime preconditions. | success: 'dotfiles-provision verify' is green when all nine done-criteria hold (install dir, binaries, CLI tools, assets, settings parse, symlinks, filesystem, compositor configs, preconditions).
- (capability) CAP-4 | intent: A fresh machine can be fully provisioned in one command. | success: 'git clone && ./scripts/bootstrap.sh' bootstraps Python+uv and completes 'dotfiles-provision bootstrap' with verify green.
- (capability) CAP-5 | intent: The three compute providers read and write through a shared install spine. | success: after provisioning, csg/weg/itr with --config <provisioned-settings> write to/read from $XDG_DATA_HOME/dotfiles/ (palettes, effects, icons) with no per-invocation path flags; ITR color_scheme.path chains to CSG palette output.
- (assumption) Hyprland, Hyprpaper, Waybar, fonts, and the csg/weg/itr CLIs are installable via Ansible on Arch and Debian-family targets.
- (assumption) uv can be pre-seeded by bootstrap.sh if absent.
- (assumption) $XDG_DATA_HOME defaults to ~/.local/share when unset.
- (assumption) Settings schema facts (per-tool settings.toml fields, env prefixes, dump commands) are verified against the current codebase and treated as the contract.
- (assumption) Wallpaper input to CSG and WEG is a positional CLI argument, never a settings field.
- (question) CSG templates placement: Option A (default, deploy to ~/.config/color-scheme/templates/ for XDG discovery) or Option B (deploy to install dir and pass --templates-dir at runtime)? Default Option A.
- (question) Should provisioning deploy a custom WEG effects.yaml, or leave WEG on its bundled default? Default: leave bundled.
