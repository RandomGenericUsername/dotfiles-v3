- (capability) CAP-1 User can set the desktop wallpaper from any image path. intent: user runs wallpaper set with an image path to change the desktop wallpaper. success: the wallpaper is applied (visible), a palette and effects are derived, configs updated, desktop reloaded, state persisted.
- (capability) CAP-2 Derived artifacts are cached by content hash. intent: the system reuses previously-derived palette/effects/icons for a wallpaper it has seen before. success: re-setting the same wallpaper (or a previously-used one) performs zero csg/weg/itr invocations and returns from the cache.
- (capability) CAP-3 Active desktop state swaps atomically. intent: changing wallpaper converges all desktop consumers (Hyprland, Waybar, Hyprpaper, terminal colors) to the new state without file copying. success: after a swap, every consumer reads the new palette/wallpaper/effects through current/ symlinks; a crash mid-swap leaves the desktop consistent and repairable on next run.
- (capability) CAP-4 Runtime state and history persist. intent: the system records the current desktop state and an append-only history of state transitions. success: current.json reflects the active state; history.jsonl has one line per reconcile, survives restarts, and is never overwritten.
- (capability) CAP-5 First-run cache self-seeding. intent: on a freshly provisioned machine, the runtime adopts the provisioning default palette/effects/icons into its cache without manual steps. success: first wallpaper set after provisioning seeds the cache from install spine output, writes current.json, and creates current/ symlinks.
- (capability) CAP-6 Desktop reload after state change. intent: the system tells running desktop components to re-read their configs after a swap. success: Hyprland reloads, Waybar restarts, Hyprpaper shows the new wallpaper, terminal applies the new palette.
- (capability) CAP-7 Runtime state is inspectable. intent: the user can view current state and history. success: commands exist to show current wallpaper/palette/effects/icons and list state history and cache contents.
- (constraint) Hexagonal architecture: dependencies point inward; domain is pure (stdlib allowlist, no os/subprocess/shutil/pathlib, no Path FS calls); ports are ABCs; layering mechanically enforced by test_layering.py mirroring provisioning. Binds all runtime code.
- (constraint) Synchronous imperative execution model for Phase 2: no daemon, async, event bus, plugin system, or distributed execution. Binds the whole pipeline.
- (constraint) Filesystem is the authority; the store is an index + history. cache/ contents and current/ symlinks are truth; current.json/history.jsonl/meta.json are re-derivable (except history). Binds persistence.
- (constraint) state_root = XDG_STATE_HOME/dotfiles/, runtime-owned. Runtime never writes under the install spine after seeding; provisioning never writes under state_root. Binds filesystem layout and both domains.
- (constraint) JSON/dict-like store only: current.json + history.jsonl + per-entry meta.json, schemas pinned in the spine's shared-data-contract.md. No SQLite, no ORM, no multi-backend. Binds persistence.
- (constraint) Content hashing is SHA-256, recorded as hash_algorithm in every meta.json; cache entry dirs named by hash of ALL derivation inputs (templates/catalog/mappings included). Binds all hashing and cache keys.
- (constraint) Swap = repoint current/ symlinks only (no copying); symlinks lead, current.json follows; swap sequence owned by ReconcileDesktopStateUseCase per shared-data-contract. Binds desktop convergence.
- (constraint) CSG/WEG/ITR output directed via env-var overrides per call (literal keys in shared-data-contract); provisioning-rendered settings.toml never edited by runtime. csg runs in container mode, override passed into container env. Binds tool integration.
- (constraint) Cross-package boundary: runtime imports only cli_output (and declared deps); never provisioning or the cli-tools packages; reads provisioning output/settings as data only. Binds package structure.
- (constraint) Runtime core is a nested-hexagon uv package at src/runtime/src/runtime/{domain,ports,adapters,application,cli} with tests/architecture/test_layering.py. Binds repo structure.
- (direction) NON-GOAL Content-hash invalidation and selective regeneration (Phase 3): Phase 2 caches but does not re-verify artifact hashes on load or do selective regeneration.
- (direction) NON-GOAL Desired-state diff engine and declarative reconciliation (Phase 4): Phase 2 is imperative, not declarative convergence.
- (direction) NON-GOAL Filesystem watchers, daemon, reactive updates (Phase 5).
- (direction) NON-GOAL Parallel execution, plugin interfaces, distributed cache (Phase 6).
- (direction) NON-GOAL Package installation, binary provisioning, filesystem bootstrap, symlink provisioning: those belong to the provisioning domain and never enter the runtime core.
- (direction) NON-GOAL Cache eviction policy and enforcement (Phase 3+); Phase 2 ships list/prune as stubs only.
- (assumption) CSG is deterministic (same wallpaper + same templates -> same palette), per docs/99:983-984. Must be verified before the cache key is trusted; if non-deterministic, add a fixed seed to the key.
- (assumption) ITR is deterministic (same palette + templates + mappings -> same icons).
- (assumption) Provisioning's rendered settings.toml for csg/weg/itr exists and is valid on a provisioned machine (verify green guarantees this per docs/99).
