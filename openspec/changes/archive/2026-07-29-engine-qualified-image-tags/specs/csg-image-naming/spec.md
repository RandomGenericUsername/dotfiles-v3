# CSG Image Naming

## Status: MODIFIED

## Previous Behavior

CSG used an inconsistent naming scheme:
- Backend images: `{prefix}color-scheme-{suffix}:{tag}` (e.g. `csgcolor-scheme-custom:latest`) — no separator between prefix and `color-scheme-`
- Base image: hardcoded as `color-scheme-base:latest` — no prefix

## New Behavior

All CSG images follow a single hyphenated scheme:
- Format: `{prefix}-{segment}-{engine}:{tag}` (e.g. `csg-custom-docker:latest`)
- Base image: `{prefix}-base-{engine}:{tag}` (e.g. `csg-base-docker:latest`)

### Engine Qualification

All image references include the engine suffix (`-docker` or `-podman`), generated by the shared `engine_qualified_image` helper.

### Backend Dockerfiles

`Dockerfile.custom`, `Dockerfile.pywal`, `Dockerfile.wallust` now use `ARG BASE_IMAGE` with a default of `csg-base-docker:latest`. The install flow passes `--build-arg BASE_IMAGE=<engine-qualified-base>` to match the base image just built.

`Dockerfile.base` is unchanged (`FROM python:3.14-slim`).

### Engine Resolution

```
engine = <--container-engine CLI override>
      or ContainerEngine(settings.container.engine)
      or ContainerEngine.DOCKER
engine_value = engine.value  # "docker" or "podman"
```

The qualifier is applied in every construction path — install, uninstall, runtime run, dry-run — using the same resolved value. There is no "skip qualifier for docker" branch.

### Migration

Pre-existing engine-less images (`color-scheme-base:latest`, `csgcolor-scheme-*:latest`) are not auto-removed. Users running both engines should uninstall old names or accept that they become orphaned.
