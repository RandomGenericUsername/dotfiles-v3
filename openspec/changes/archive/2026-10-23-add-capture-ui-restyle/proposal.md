## Why

The capture tool (`src/gui-tools/capture-tool/`, AGS instance `capture`) is functionally complete but visually bare: every choice is a generic `Gtk.Button` stacked vertically — no icons, no selection hierarchy, no mode identity, and the Audio/Duration rows plus GIF handling exist only as decoration. The HTML mockups in `spikes/capture-tool-ui/` (reviewed and approved in-browser) define the target visual language: mode-first switch, icon target tiles, label-left/segmented-pill settings rows, a loud mode-tinted primary action, and a GIF special case — all dressed in the shell's existing "hypr-pano" vocabulary and driven exclusively by the runtime `@color_*` palette tokens.

Three gaps block the port: (1) the capture GUI has no icon pipeline — the deployed `ags-capture` spine carries no `icons.json` and no `lib/icon-registry.ts`, so it cannot resolve palette-aware icons at all; (2) the icon inventory itself is split across two dead-or-duplicate namespaces (`screen-recorder` consumed by the bar, `screenshot-tool` consumed by nothing); (3) the backend CLI accepts no `--audio`/`--duration` flags and has no GIF pipeline, so the recording view's richest rows cannot function.

## What Changes

- **One icon namespace `capture-tool`** with 14 variants from user-provided art (`~/Downloads/recorder-icons/` + `info.svg`): mode (`camera`, `video`), targets (`region`, `monitor`, `window`), screenshot output (`clipboard`, `save`), recording audio (`speaker`, `mic`), feedback (`info`, `warning`), transport (`pause`, `play`, `stop`). Templates carry `{{COLOR_FOREGROUND}}`/`{{COLOR_ACCENT}}` placeholders (converter step from the fixed `black`/`white` source art); the group declares `color_mappings` in `icons.yaml`.
- **Retire `screen-recorder` and `screenshot-tool` icon groups**: the bar's recording indicator resolves `pause`/`play`/`stop` from `capture-tool` instead; the 5 legacy `screenshot-tool` variants (unconsumed by any widget) are deleted along with their templates, manifest entries, verify expectations, and editor-test fixtures.
- **Provisioning for capture icons**: `compositor_configs` generates a second `icons.json` into the `ags-capture` spine dir from the same deployed manifest; `gui_tools` deploys `lib/icon-registry.ts` (+`lib/` dir) alongside the capture app sources with the same repo-authoritative discipline; `verify` entries updated.
- **Restructured `CaptureWindow.tsx`** to the mockup IA: Screenshot/Recording mode-switch header with icons; Region/Screen/Window as icon tiles; settings as label-left/segmented-pill rows; GIF mode removes the Audio row, narrows FPS to 10/15/20/30, adds a Size row, and shows an explanatory notice; footer with `Esc`/`Enter` hints.
- **`style.css` port** of `spikes/capture-tool-ui/mockup.css` onto `@color_*` tokens (panel translucency, tiles, pills, mode-tinted primary CTA, notice, footer).
- **Config persistence**: last-used screenshot/recording choices remembered across launches (doc §37 of the project plan).
- **Backend capabilities**: `capture-tool start` gains `--audio` and `--duration`; GIF is implemented as its documented special pipeline (frame-rate band + scale), not as a recorder passthrough.

## Capabilities

### New Capabilities

- `capture-icons`: the single `capture-tool` icon group (templates, manifest registration, placeholder conversion, retirement of the two legacy groups, registry consumption, provisioning generation, verification).
- `capture-ui`: the restructured capture window (layout, GIF mode, keyboard contract, config persistence, token-driven stylesheet).
- `capture-backend-options`: backend support for audio source, finite duration, and the GIF special pipeline.

### Modified Capabilities

*(None — no existing capability contracts are altered; the bar's registry group reference moves to the new namespace as part of `capture-icons`.)*

## Impact

- **Icons** (`dotfiles/assets/icon-templates/`, `dotfiles/config/icon-template-color-scheme-mappings/`): new `capture-tool/default/` template tree (14 SVGs); `icons.yaml` gains the group and loses `screen-recorder` + `screenshot-tool`; `icons.json` regenerated by provisioning.
- **Bar** (`dotfiles/config/ags/bar/widgets/recording.tsx`): `registry.resolve("screen-recorder", …)` → `("capture-tool", …)` — the only code change in the bar app; new art appears with no layout edits (full restyle is Change 2).
- **GUI** (`src/gui-tools/capture-tool/`): `ui/CaptureWindow.tsx` restructured (icons, GIF mode, audio/duration state wiring, keyboard controllers); `style.css` rewritten from the mockup sheet; config persistence added.
- **Runtime** (`src/runtime` + `src/gui-tools/capture-tool/bin/capture-tool`): `--audio`, `--duration`, GIF pipeline; unit tests mirroring the existing capture tests.
- **Provisioning**: `compositor_configs` second-manifest task; `gui_tools` per-file list gains `lib/icon-registry.ts` and the `lib/` dir; `verify` expected-files updated (capture spine additions, legacy group removals); related unit tests (`test_verify_role.py`, editor `templates.mjs` fixtures) updated.
- **AgsReloader**: no changes — it already restarts the `capture` instance on palette change; the new GUI inherits dynamic theming by using `colors.css` tokens like every other surface.
- **Out of scope**: bar indicator restyle/popup (Change 2), notifications (Change 3), annotation/history/settings-page surfaces, codec expert settings.
