# CSG Image Naming

## Why

CSG previously used an inconsistent naming scheme where backend images lacked a separator between prefix and segment (e.g. `csgcolor-scheme-custom`) and the base image had no prefix at all (`color-scheme-base`). This was normalized to a consistent hyphenated scheme.

## Current Behavior

All CSG images follow a single hyphenated scheme:
- Format: `{prefix}-{segment}-{engine}:{tag}` (e.g. `csg-custom-docker:latest`)
- Base image: `{prefix}-base-{engine}:{tag}` (e.g. `csg-base-docker:latest`)

### Engine Qualification

All image references include the engine suffix (`-docker` or `-podman`), generated by the shared `engine_qualified_image` helper in `oci_runtime`.

### Backend Dockerfiles

`Dockerfile.custom`, `Dockerfile.pywal`, `Dockerfile.wallust` use `ARG BASE_IMAGE` with a default of `csg-base-docker:latest`. The install flow passes `--build-arg BASE_IMAGE=<engine-qualified-base>` to match the base image just built.

`Dockerfile.base` is unchanged (`FROM python:3.14-slim`).

### Engine Resolution

```
engine = <--container-engine CLI override>
      or ContainerEngine(settings.container.engine)
      or ContainerEngine.DOCKER
engine_value = engine.value  # "docker" or "podman"
```

The qualifier is applied in every construction path — install, uninstall, runtime run, dry-run — using the same resolved value. There is no "skip qualifier for docker" branch.
