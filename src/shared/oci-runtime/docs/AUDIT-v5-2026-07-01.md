A full audit of `src/shared/oci-runtime/`, contrasted against the git history
and the archived v1–v4 OpenSpec changes so the remediation does not loop.

quality. Each finding cites `file_path:line_number` where possible.

## 1. Hexagonal Architecture

### 1.1 CIRCULAR — `domain/build_tar.py` does I/O (was already fixed once)

- `domain/build_tar.py:1-3` imports `io`, `os`, `tarfile`.
- `domain/build_tar.py:8-9` calls `os.path.normpath`/`os.path.isabs`.
- `domain/build_tar.py:25` calls `tarfile.open(...)` on a `BytesIO`.

History: fix `7eafd50 (#17) "extract create_build_tar to adapters/_tar.py"`
moved this out of domain in v2. Then v3 commit `1953540 "relocate
cancellation & pipe_reader to ports"` **reverted** that extraction — it
deleted `adapters/_tar.py` wholesale, putting `create_build_tar` back into
`domain/` verbatim. v4 did not re-address this. This is the clearest example
of a circle; whatever the resolution, it must be specced and the layering
test must close the loop.

### 1.2 PERSISTENT — `pathlib.Path` in `domain/types.py`

- `domain/types.py:3` imports `pathlib.Path`; used as field type at
  `:36,37,79,80,89`.
- Survives v1–v4. Decide deliberately: is `Path` a value object (allowed in
  domain) or a stdlib I/O abstraction (banned)? Either way, document it in
  ARCHITECTURE.md's allowed-stdlib list (which currently omits `pathlib`).

### 1.3 VALID VIOLATION — `ports/{pipe_reader,cancellation}` concrete classes (re-extract in A3)

- `ports/pipe_reader.py:21` `ProcessPipeReader` does `os.read` (`:58`).
- `ports/cancellation.py:16,30,58` `ThreadCancellationToken`,
  `DeadlineCancellationToken` (starts a real `threading.Timer` at `:40`),
  `CompositeCancellationToken`.

Hexagonal `ports/` is the interface boundary; `os.read` and
`threading.Timer` in `ports/` are violations regardless of where the spec
codified them. v3 commit `1953540` relocated these to ports/ "for
testability" — empirically false: tests patch the adapter module's
binding (`"oci_runtime.adapters.transport.cli.ProcessPipeReader"`), not
the class source location. The relocation added zero testability. **See
A3 resolution in §4: re-extract to adapters/, supersede
`oci-pipe-reader-port`.**

### 1.4 PERSISTENT — layering test is decorative (`tests/architecture/test_layering.py`)

- `:35-41` `_ALLOWED_TARGETS["adapters"]` omits `"adapters"`, contradicting
  the docstring at `:8`.
- Only inspects `oci_runtime.*` imports — never stdlib. Does not catch the
  `io`/`os`/`tarfile`/`pathlib` use in `domain/build_tar.py`, nor would it
  catch any future `subprocess` import.
- No rule on what may live in `ports/` (no abstractness check), so the
  concrete classes in §1.3 (accepted) would slip past silently if they were
  bugs instead. Not currently reachable by `gate` rule.
- Self-run: `OK: 58 source files, no layering violations` despite all the
  above.
- Survives v1–v4 unaddressed (v4 only touched factory/provider/public-API
  facets of `oci-strict-hexagonal-layering`, not the layering test itself).

### 1.5 SYMPTOM OF A3 — adapters depend on concrete `ProcessPipeReader`/`DeadlineCancellationToken`

- `adapters/transport/cli.py:14`, `streaming.py:13`, `pty.py:17` import
  concrete `ProcessPipeReader`; `cli.py:35`, `streaming.py:36`,
  `pty.py:39` instantiate `DeadlineCancellationToken` directly.

This is a symptom of A3 (concrete classes living in ports/), not a
separate architectural decision. Resolves automatically when A3
re-extracts the concretions to adapters/.

### 1.6 PERSISTENT — factory type narrowing weak

- `factory.py` still uses `type | None` for manager slots at the
  config-record level (was M1 in v4 — partially resolved by
  `ResolvedRuntimeFactoryConfig` but the public `RuntimeFactoryConfig`
  shape remains untyped at the boundary).
- Survives because the public-API shape is frozen; the resolved shape is
  internal-only.

## 2. Bugs & Bad Implementations

### 2.1 PERSISTENT — bugs missed by every prior cycle

These are **new** findings, none of them appear in v1–v4 proposals:

- **`adapters/managers/image.py:39-41`** — when `BuildContext.build_file_path`
  is set without `context_path`, the user-supplied `files` mapping is
  silently dropped and `create_build_tar` is never called. No regression
  test, no spec.
- **`adapters/managers/image.py:45,48`** and **`adapters/transport/pty.py:54`**
  — bare `assert x is not None` before `.encode`/`.fileno`. Stripped by
  `python -O`, so production runs leak `AttributeError` instead of the
  contract error.
- **`adapters/parser/docker.py:281`** — `raw_ports = item.get("Ports", [])`
  then `for p in raw_ports`. If Docker emits `"Ports": None`, loops crash
  with `TypeError` (the `.get` default only fires on missing key, not on
  explicit `None`). v4 fixed string-Ports (B5), not `None`-Ports.
- **`adapters/managers/container.py:213,226`** — `str(int(timeout))`
  truncates fractional timeouts (`stop(timeout=1.9)` → `"1"`). No spec
  covers timeout precision.
- **`adapters/managers/container.py:169-191`** — `RunConfig(stream_output=True,
  detach=True)` is silently mis-handled: `-d` is appended, the streaming
  branch runs, the detached process exits, and `run` returns `""`. No
  validation, no spec for the invalid combo.
- **`adapters/managers/container.py:303-329`** — `logs(follow=True)` worker
  thread mutates a plain `errors` list with no lock while the consumer
  thread reads `errors[0]`. v4's `L21` added a cancellation test but
  untouched for this race.
- **`domain/json_parsing.py:32-50`** — `except json.JSONDecodeError: pass`
  then the line-by-line fallback raises misleading `ParsingError` on an
  indented multi-line `--format json` payload. Distant cousin of #19
  ("fail fast on malformed NDJSON lines") — different shape: indented
  pretty-printed single-object output.

### 2.2 PERSISTENT — resource leaks still present after v4

- **`adapters/transport/{cli,streaming,pty}.py` cancellation branches** —
  `process.kill(); process.wait()` with **no timeout**. If the child is in
  D-state or zombie-parented, the calling thread blocks unboundedly. v4
  added M2 (`cli.py` final-kill) but did not add `wait(timeout=...)`.
- **`adapters/transport/pty.py`** — still has no `_process_reaped` flag at
  all (cli.py and streaming.py have it). The `finally` always closes
  `process.stdout/stderr/stdin` even after clean exit → double-close
  tolerated only by Python's pipe-guard. Drifted from cli/streaming siblings,
  uniquely vulnerable.

### 2.3 PERSISTENT — duplication/drift (~200–340 LOC)

- **3× transport scaffold** (`cli.py` 135 LOC, `streaming.py` 137, `pty.py`
  125). Popen setup + write-thread + reader + cancel loop + finally-pipe
  cleanup copied three times. The 2.2 leak and `pty.py`-missing-`_process_reaped`
  are direct copy-paste fallout. Never remediated; v4 only touched the
  timeout-poll branch.
- **`provider/docker.py` (55) ≈ `provider/podman.py` (56)** — 95%
  structurally identical, differ only in enum kind and capability fields.
  Partially addressed by `8bc7be1 (#25) "BaseCliRuntimeProvider"` but the
  subclasses remain near-verbatim.
- **Parser scaffolding divergence** — Docker `_parse_docker_ports_*` as
  module-level free functions (`parser/docker.py:241-333`) vs Podman
  `_parse_ports` as methods (`parser/podman.py:28-88`). Different naming,
  different code style, no shared port-parsing helper in `domain/`.
- **`adapters/engine/cli.py:58,63`** decodes inline
  (`result.stdout.decode("utf-8", errors="replace")`) instead of reusing
  `domain/encoding.safe_decode`. v4 shipped encoding fixes but didn't push
  this call site through the helper.

### 2.4 PERSISTENT — code patterns

- **No `Cmd`/`Subcommand` enum** — `"run"`, `"build"`, `"inspect"`, etc.
  scattered string literals across all four manager adapters. A typo
  (`"inspec"`) is uncatchable at static typecheck.
- **`domain/exceptions.py:73-88`** — `*NotFoundError` subclasses ignore
  `command`/`exit_code`/`stderr` while `ImagePullAccessDeniedError` uses
  them. v4 A4 wired it forward but the rest of the family still drops
  context.
- **`domain/result_checking.py:31`** — `raise not_found_error(entity)`
  with no context, contradicting `:24` `auth_error(entity, command=...,
  exit_code=..., stderr=...)`. v4 created ProviderNotRegistered but left
  this inconsistency.
- **Magic numbers** — 5s stdin join (`cli.py:129`, `streaming.py:84,94`),
  10s default timeout (`container.py:213,226`), 4096 read size
  (`ports/pipe_reader.py:56`). No constants module.

### 2.5 V4 REGRESSION — and what was closed (so we do not undo v4)

Already closed by v4 — **do not re-open**:

- A4 auth-context, ProviderNotRegisteredError, R1 port-side `output_stream`,
  B1 prune `Deleted:` capitalization, H3 timeout race (`process.poll()`
  check), B3 memory-limit regex, B5 Docker `Ports`-as-string, B4
  `_freeze_mapping` aliasing, H1 `matches_any_pattern` case, H2 Podman
  host_ip binding, M6/M7 pipe-reader edge handling, M1 factory
  resolved-config type narrowing, M5 `capabilities` property, M8 public
  API re-exports, M9 real parsers in wiring, M10 exec-assert, L20 ruff
  cleanup, M11 conformance fixtures, M12 smoke parity over runtimes.

The fresh findings in §2.1 must avoid touching these to prevent a
back-slide.

## 5. Resolutions (2026-07-01)

All decisions below were reviewed finding-by-finding and locked with the
architectural reasoning (not git-history deference). Summary replacement
of §1.3, §1.5, and §2.5 (which previously laundered two real violations
as "accepted design" — those labels are **withdrawn**; see corrections at
the bottom of this section).

### Architectural resolves

| Finding | Decision | Reasoning summary |
|---|---|---|
| **A1** `domain/build_tar.py` does I/O via `os.path`, `tarfile` | **(a) posixpath swap, keep in domain** | `os.path` is environment-coupled (pos/nt dispatch); `posixpath` is pure string math. `tarfile.open(fileobj=BytesIO(...))` is pure encode. Function's contract is bytes-in/bytes-out → domain-resident. Do NOT re-extract to adapters (that's the v2→v3 circle). The A4 layering test enforces via stdlib allowlist. Break the circle by allowlisting rather than relocating. |
| **A2** `pathlib.Path` as field types in `domain/types.py` | **(a) Allowlist `pathlib`, AST-ban FS-method calls** | `Path` is a value object as a field type; FS-touching methods (`Path.exists`/`read_text`/`glob`/`mkdir`/`iterdir`) are not called in domain today. The allowlist locks `pathlib`; a separate AST rule forbids FS-method calls on `Path` inside `domain/`. Turns "we decided" into "we enforced" — without that the rule relies on the same discipline that let A1 and A3 slip. |
| **A3** Concrete adapter classes living in `ports/` | **(a) Re-extract to adapters/, supersede v3 spec** | Hexagonal `ports/` holds interfaces; `os.read` and `threading.Timer` in `ports/` is a violation. v3's "for testability" rationale is empirically false — tests patch the adapter module's binding (`"oci_runtime.adapters.transport.cli.ProcessPipeReader"`), not the class's source location. The relocation added zero testability and one violation. Re-extract `ProcessPipeReader` → `adapters/transport/pipe_reader.py`; `ThreadCancellationToken`/`DeadlineCancellationToken`/`CompositeCancellationToken`/`compose_tokens` → `adapters/cancellation.py`. ABCs stay in `ports/`. New spec `oci-cancellation-adapter-relocation` **explicitly supersedes** `oci-pipe-reader-port` (v3). 6 import edits. After this, `ports/` is mechanically verifiable as ABCs-only + the two typed-dataclass aggregates (`Parsers`, `RuntimeCapabilities`) — no carve-out in A4. |
| **A4** Layering test decorative | **(a) Strengthen with stdlib allowlist + banned-stdlib + ports-ABC rule** | Three new mechanical rules: (1) domain stdlib imports MUST be in `_DOMAIN_ALLOWED_STDLIB = {posixpath, io, tarfile, pathlib, json, re, dataclasses, collections, collections.abc, types, enum}` — allowlist, additions require spec edit; (2) domain MUST NOT import `subprocess`/`os`/`shutil`/`select`/`selectors`/`socket`; (3) every `ports/*.py` class MUST inherit `abc.ABC` with `@abstractmethod` OR be a `@dataclass`-typed aggregate. Plus fix `_ALLOWED_TARGETS["adapters"]` docstring inconsistency. No carve-out — A3's re-extraction makes `ports/` pure. Must land **before** A1 and A3 (TDD red→green). |
| **A5** `RuntimeFactoryConfig` public type `type | None` lies to mypy | **(b) Builder pattern** | v4 M1's `ResolvedRuntimeFactoryConfig` is internally typed-truthful; the public record still lies. Deprecate direct `RuntimeFactoryConfig` construction; expose `RuntimeFactoryConfigBuilder.build() -> ResolvedRuntimeFactoryConfig`. Public API becomes typed-truthful end-to-end. API break accepted (the internal-code dishonesty of calling the public shape "resolved" was the alternative — that framing was wrong). |

| Finding | Decision |
|---|---|
